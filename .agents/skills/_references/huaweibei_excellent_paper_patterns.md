# 华为杯优秀论文范式与官方模板要求（对标国一）

本文件把三类信息严格分开，引用时必须保留标签：

- **[官方]**：来自竞赛官方论文模板（2025 年第二十二届官方 Word 模板副本）中的明文要求。每届通知可能变化，开赛后必须用当届官方模板/通知重新核对，核对结果记入 `todo.md`。
- **[样本]**：对 2023–2024 年公布的 75 篇优秀论文（A–F 题均有，2023 年 57 篇、2024 年 18 篇）做结构统计和抽样阅读得到的观察。它们描述"获奖论文长什么样"，不是评分规则，也不构成硬性阈值。
- **[建议]**：本工作台据此给出的内部推荐做法。写作和验收 skill 按"建议"执行，但违背"建议"只记 `WARN`，违背"官方"记 `FAIL`。

正文中不得出现本文件名或"优秀论文样本"之类的过程性表述。

## 1. 官方模板明文要求 [官方]

来源：官方 Word 论文模板（第二十二届版）。以下为模板内的明文规定或示例格式，逐条列出：

1. **标题**：一般写成"基于 XXX 模型/方法/理论的 XXX 问题研究"。
2. **摘要**：包含前言（3–5 行背景与主要问题）、正文（逐小问：建模过程与求解思路、结果）、结尾（创新点/优缺点/推广）；**摘要不超过两页**；关键词 3–5 个（研究对象、主要模型、求解算法）。
3. **问题重述**：用自己的话改写，半页到一页；这是查重最容易出问题的部分，不得照抄题面。
4. **问题分析**：每个问题单独一小节，简明扼要，不放结论；建议配总体分析流程图。
5. **模型假设**：五类常见假设——数据保真性、只考虑主要条件、平稳性规定、常识性简化、参数规定。
6. **符号说明**：三线表，含"符号 / 说明 / 单位"三列；只列全局变量；符号在正文首次出现处仍需说明。
7. **模型建立与求解**：模型要正确、简明、可解、实用；"不要追求数学上的难度"；每问内含 数据预处理 → 模型建立 → 模型求解 → 模型检验 → 结果分析。
8. **公式**：务必用公式编辑器，**不得截图**。
9. **模型检验**：单列一章，包含 稳定性与敏感性分析、统计检验与误差分析、新旧模型对比。
10. **模型优缺点评价**：优点说充分、缺点不回避；缺点后给改进思路。
11. **参考文献**：按 GB/T 7714 类型标注（[M] [J] [C] [D] [P] [R] [S] 及电子文献）。
12. **AI 工具使用声明（最重要的新增要求）**：
    - 使用 AI 工具生成的内容，须在**正文相应位置**标注（模板示例写法：`（该部分数据分析结果使用AI工具：DeepSeek, DeepSeek-R1-0528, 深度求索（DeepSeek）, 2025-09-05）`）；
    - 在**参考文献**中列出所用 AI 工具，格式：`[编号] 工具名称, 版本/型号, 开发机构/公司, 使用日期`；
    - 附录代码若由 AI 生成，同样在该段代码前标注。
13. **附录**：附录 1 = 支撑材料文件列表；附录 2+ = 源代码（说明语言与作用）；还可放详细证明、外部数据、大流程图、繁杂图表。

> 本工作台由 AI 驱动，因此第 12 条是硬约束：`math_modeling_norms.md` 中"正文不得出现'由 AI 生成'等过程痕迹"的通用规则在华为杯场景下**让位于官方声明要求**——过程性文件名仍然禁止出现，但 AI 工具声明必须按官方格式出现。

75 篇优秀论文（文件名 `[A-F]\d{2}…`）的自动统计（中位数 / 均值 / 范围）：

| 指标 | 中位数 | 均值 | 范围 |
| --- | ---: | ---: | ---: |
| 总页数 | 68 | 72 | 42–138 |
| 正文页数（到参考文献止） | 47 | 49 | 26–113 |
| 附录页数 | 15 | 18 | 0–72 |
| 摘要字数（字符） | 1417 | 1448 | 676–2796 |
| 摘要中的数字个数 | 7 | 8.6 | 0–28 |
| 关键词数 | 5 | 4.5 | 0–9 |
| 子问题数 | 6 | 5.9 | 3–10 |
| 图 | 30 | 34 | 2–78 |
| 表 | 12 | 15.5 | 0–65 |
| 编号公式 | 32 | 42 | 0–167 |
| 参考文献 | 12 | 13.5 | 0–46 |

按年份：2023（57 篇）正文中位 44 页、图 29、表 12、公式 33、文献 12；2024（18 篇）正文中位 52 页、图 39.5、表 10.5、公式 26、文献 13。

章节出现率（按目录识别）：问题重述 99%、模型建立 93%、模型求解 96%、符号说明 88%、附录 88%（其中含代码 76%）、模型评价 79%、模型假设 75%、问题分析 72%、结果分析 48%、误差/验证 16%、独立的灵敏度/稳健性章 8%。

解读（[样本] → [建议]）：

- 篇幅明显长于本科国赛：正文 40–55 页是常态，图 30 张左右、表 10–15 张。**篇幅本身不是目标**，但正文 < 25 页或图 < 10 张时应自查是否缺少结果分析与对比。
- **只有 8% 有独立"灵敏度分析"章**，但抽样阅读发现验证/对比/鲁棒性检验普遍嵌在各小问的"结果分析"里（见 §4）。因此不要机械要求独立章节，而要求**每个主模型至少有一处验证证据**（误差、基线对比、扰动检验或约束满足性之一）。
- 参考文献中位 12 篇，全部真实可查；不追求数量。

## 3. 摘要范式 [样本]

抽样阅读 2024 年 A–F 六篇及若干 2023 年论文，摘要的共同结构：

1. **首段**：背景 2–3 句 + 本文总体思路 1 句（"本文面向 X 任务，以 Y 为例，从 U/V 两个尺度建模……"）。
2. **逐小问一段**，固定句式 `针对问题 N，首先……随后/其次……最后……`，每段包含：
   - 该问的核心矛盾或输入（常引用前一问的输出："基于问题二得到的……"）；
   - 方法名 + 关键改进点（不是只报方法名）；
   - **可核验的数值结论**：至少一个数字（误差/指标/最优值/分类计数/耗时等），或明确的定性结论；
   - 验证动作："与基线对比…""相似度达…""求解时间由 X 降至 Y""在 ±10% 扰动下…"。
3. **尾段**（部分论文）：模型总结、优缺点或推广 1–3 句。
4. **关键词** 3–7 个：研究对象 + 主要模型 + 算法。

摘要长度 1200–1800 字符、含 5–10 个数字是主流；数字必须与正文冻结结果一致。

[建议] 摘要写作模板（每问一段）：

```text
针对问题 N，<该问要解决的矛盾/目标>。首先<数据处理或前置分析>，随后<建立 X 模型 / 提出 Y 改进>，
最后<求解或验证方式>，得到<关键数值结论>；与<基线/其他方案>相比，<改进幅度或权衡>。
```

## 4. 小问章节范式 [样本]

高分论文每个小问的内部结构高度一致：

```text
N.1 问题分析          —— 该问难点、与前问的衔接、输出形式
N.2 模型建立          —— 基础模型 → 针对本题的改进/修正（公式编号，符号即定义）
N.3 模型求解          —— 算法步骤/流程图、参数设置、求解规模
N.4 结果分析与验证    —— 数值/图表 + 与基线或多种方案对比（精度 × 时间 × 约束满足性）
                        + 误差/鲁棒性/灵敏度检验（如噪声、延迟、扰动、跨数据集）
N.5 问题小结          —— 2–5 句回答题目原问，交代给下一问的输入
```

典型做法：

- **递进链**：前一问的结果（如疲劳损伤指标、时延模型、温度修正方程）显式成为后一问的输入，摘要和小结都点明这一链条；模型评价里把"层层递进、环环相扣"作为优点写出。
- **多方案对比**：同一问给 2–3 种方案（如 传统方法 / 改进方法 / 数据驱动方法），用同一套指标横向比较，并说明取舍（精度 vs 实时性）。
- **验证嵌在小问里**：噪声/延迟鲁棒性、跨数据集泛化、参数敏感性、约束校验、与官方参考方法对比，通常作为该问的一个小节，而非全文末尾一章。
- **结果回到题意**：结论用题目的语言回答（"满足实时性要求""可为调度提供参考"），而不是只报算法指标。
- **模型评价**写具体：优点对应本文的实际做法（"考虑了 X 约束""引入 Y 修正后误差降至 Z"），缺点指出未考虑的因素并给改进方向。

[建议] 写作阶段以此为每个 `N_problemX` 章节的默认骨架；验收阶段检查每问是否具备 N.4（含至少一种验证）和 N.5。

## 5. 图表与公式 [样本]

- 图：技术路线/总体流程图 1 张 + 每问 3–8 张（数据可视化、方法示意、结果对比、误差分布）。对比图常把多种方案画在同一坐标系。
- 表：符号说明表、数据概况表、参数设置表、结果对比表（含基线列）、误差指标表。
- 公式：每问 5–15 个编号公式，方法核心公式必须出现；符号紧随定义。
- 图表题格式与官方模板一致；图表均被正文引用且引用前有引导句。

## 6. 验收对标清单 [建议]

写作/验收 skill 对华为杯论文执行以下检查，标签指明失败等级：

| 检查项 | 等级 |
| --- | --- |
| 参考文献含 AI 工具条目（工具名、版本/型号、机构、日期），正文 AI 生成内容处有标注 | FAIL |
| 摘要 ≤ 2 页；每个小问在摘要中有一段且含至少一个可核验数字或明确定性结论 | FAIL（缺小问）/ WARN（无数字） |
| 关键词 3–7 个 | WARN |
| 符号说明表含"单位"列 | WARN |
| 公式为文本/公式对象，无公式截图 | FAIL |
| 每个主模型至少一种验证证据（误差、基线对比、扰动/灵敏度、约束满足性） | FAIL |
| 每个小问有"结果分析"与"小结"，小结回答题目原问 | WARN |
| 存在"模型检验"或等价内容（灵敏度/误差/新旧对比），可分布在各问 | WARN |
| 模型评价：优点与本文具体做法对应，缺点 + 改进方向 | WARN |
| 附录 1 为支撑材料文件列表；代码附录说明语言与作用 | WARN |
| 正文 < 25 页或图 < 10 张 | WARN（提示自查） |
| 问题重述与题面高度重合（整段照抄） | WARN |
| 队号/学校出现在封面以外 | FAIL |
